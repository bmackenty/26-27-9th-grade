# Scope Statement

Fill this in **before you write any code**, and get it approved. Yes, before.

Scoping is an engineering skill, not paperwork. A small finished program
teaches you more than a large unfinished one, and a large unfinished one is
also much harder to mark.

---

## The Core-First Scope Model

| Layer | What it means | Rule |
| --- | --- | --- |
| **Core** | The smallest version that is genuinely useful | Must work before anything else starts |
| **Extension** | The next most valuable feature | Only after Core is stable and committed |
| **Ambition** | The thing you would love to add | Optional. Never at the cost of Core. |

The most common Grade 9 project failure is starting on Ambition in week one.
The second most common is Core still not working in the final week.

```
Name:

EXPLICITLY OUT OF SCOPE (one thing I am deciding NOT to do)

```

## Examples

**Too big:** "A social network for the school where students post projects and
comment and get notifications and there is a leaderboard."

**Too small:** "A program that prints my name."

**About right:** "A program that reads a CSV of my football team's results and
prints how many games we won at home versus away."

Small and finished. Then extend it.
